# Inventory & Order Management API

Стартовый проект для хакатона. Это небольшой сервис управления товарами, складскими остатками и заказами.

## Стек

- Go 1.23+
- PostgreSQL 16
- REST API (`net/http`)
- Docker Compose

## Запуск

```bash
docker compose up --build
```

В другом терминале примените миграцию:

```bash
make migrate-up
```

API будет доступно на `http://localhost:8080`.

Проверка:

```bash
curl http://localhost:8080/health
```

## API

### Создать товар

```bash
curl -X POST http://localhost:8080/products \
  -H 'Content-Type: application/json' \
  -d '{"sku":"KB-001","name":"Keyboard","price_cents":4999,"stock":10}'
```

### Получить товары

```bash
curl http://localhost:8080/products
```

### Создать заказ

```bash
curl -X POST http://localhost:8080/orders \
  -H 'Content-Type: application/json' \
  -d '{"customer_email":"user@example.com","items":[{"product_id":1,"quantity":2}]}'
```

### Получить заказ

```bash
curl http://localhost:8080/orders/1
```

### Отменить заказ

```bash
curl -X POST http://localhost:8080/orders/1/cancel
```

## Бизнес-правила

1. SKU товара уникален.
2. Цена задаётся в минимальных денежных единицах (например, центах), не в `float`.
3. Нельзя создать заказ с пустым списком позиций.
4. Количество каждой позиции должно быть положительным.
5. Нельзя зарезервировать больше товара, чем есть на складе.
6. При успешном создании заказа остатки должны уменьшаться.
7. При отмене заказа зарезервированные остатки должны возвращаться.
8. Повторная отмена заказа не должна повторно возвращать остатки.
9. Заказ и все его позиции должны сохраняться согласованно.

## Задание

Перед вами существующий сервис. Изучите код и улучшите его так, чтобы он был надёжным при параллельной работе и корректно обрабатывал ошибки.

Не ограничивайтесь исправлением очевидных проблем. Сначала разберитесь в текущем поведении, сформулируйте найденные риски, расставьте приоритеты и обоснуйте изменения.

Ожидается, что команда:
- сохранит совместимость API либо документирует обоснованные изменения;
- добавит тесты на исправленное поведение;
- сможет объяснить выбранные решения и их компромиссы;
- предоставит инструкции по запуску и проверке.

Организатор может выдать дополнительные требования во время хакатона.
